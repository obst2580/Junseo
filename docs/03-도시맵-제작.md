## 1. 한눈에

| 단계 | 도구 | 하는 일 |
|---|---|---|
| 뼈대 생성 | **Arnis** (실제 지도 OpenStreetMap → 마크 월드) | 도로·건물·지형을 **몇 분** 만에 1블록=1m로 생성 |
| 데이터 보강 | **국토부 GIS건물통합정보** (공공누리 1유형) | 한국 도시는 OSM 건물이 부족하므로 층수가 있는 건물 데이터로 보강 |
| 랜드마크 | 빌드 서버(Paper) + WorldEdit/FAWE·Axiom | 직접 짓기 (이 프로젝트의 정체성) |
| 채우기 | 라이선스가 확실한 건물 팩, 직접 의뢰 | 생성된 박스형 건물을 예쁜 건물로 교체 |
| 마무리 | Chunky(미리 생성), 월드 경계, 서버 설정 | 렉 줄이기 |

예상 기간 [추론]: 플레이 가능한 MVP 4~8주, 완성도 높은 도시 3~6개월(빌더 3~5명 기준).

## 2. 뼈대: Arnis (실제 지도 → 마크 월드)

- **만들어 주는 것:** 도로(차선 수 반영), 건물(지붕 포함), 토지이용, 물, 철도, 나무, 표지판. 지형 높이도 반영합니다. [원문]
- **스케일:** 기본 1.0 = 실제 크기(1블록 = 1m) [원문]
- **속도와 용량:** 4km²는 25초·70MB, 25km²는 47초·415MB (개발자 측정) [원문]
- **랜드마크 교체 기능:** 엉성한 랜드마크를 직접 만든 `.schem`으로 자동 교체할 수 있습니다. Wikidata ID로 매칭하고, Apache-2.0 라이선스라 포크해서 우리 랜드마크를 넣을 수 있습니다. [원문]
- **높이 한계:** 바닥이 Y=-62라서 약 380m보다 높은 건물(롯데월드타워 등)은 잘립니다. 랜드마크로 따로 처리합니다. [원문·추론]
- **버전 주의:**
  - Arnis는 **1.21.1 형식의 월드**를 출력합니다. [원문]
  - 26.x 서버가 열면 새 저장 구조로 자동 변환되고, **되돌릴 수 없습니다.** [요약·추론]
  - 반드시 **백업한 뒤 로컬 Paper 26.2에서 먼저 열어 보고** 옮기세요.
- **꺼 둘 옵션:** 실내 생성, 외벽 사진(CC BY-SA 라이선스 문제), 과한 3D 소품. 엔티티가 많아지면 렉이 생깁니다. [원문·추론]
- **출처 표기 의무:** 접속 화면이나 웹사이트에 "© OpenStreetMap contributors"를 꼭 표기해야 합니다(ODbL). [요약]

### 한국 도시를 쓸 때
- 한국은 OSM에 등록된 건물이 적습니다. 한 보고에 따르면 7.6%이고, 시점은 확인하지 못했습니다. [요약]
- **보강 방법** [추론, 확인 필요]
  1. data.go.kr에서 「국토교통부_GIS건물통합정보」를 받습니다. 층수가 들어 있고, 공공누리 1유형이라 출처만 표시하면 상업 이용도 가능합니다. [요약]
  2. QGIS로 OSM 형식(`.osm`)으로 바꿉니다.
  3. OSM 도로 데이터와 합쳐 `arnis --file 도시.osm`으로 생성합니다.
- **GTA 방식 권장:** 실제 지명이나 브랜드를 그대로 쓰기보다 **패러디 도시**로 각색하는 편을 권합니다. 예: 종로·용산·강남 일부를 4×4km 안에 압축합니다. [추론]

**원칙:** 라이선스가 없으면 "쓰면 안 됨"이라고 생각하고, **만든 사람의 허락**을 받으세요.

| Planet Minecraft | 작품마다 다름(CC 계열). 비상업(NC)이면 수익형 서버는 허락이 필요합니다 [요약] |

| Abfielder 도시 팩 | 상업 이용은 서면 허락이 필요합니다. 상품별로 확인하세요 [요약] |
| Varuna | 10명 초과나 수익화하면 **상업 라이선스**가 필요합니다 [요약] |
| BuiltByBit 유료 팩 | 기본 EULA는 상업 서버 사용과 수정을 허용하고 재배포는 금지합니다. 판매자별 약관을 확인하세요 [요약] |
| Greenfield 같은 유명 도시 맵 | 서버에 쓰려면 크레딧이 필요하고, 일부만 가져다 쓰거나 수익을 내려면 **서면 허락**이 필요합니다 [요약] |

**정리** [추론]
- 수익형이거나 공개 서버라면 **유료 팩(약관 보관) + 직접 의뢰 + 직접 건축** 조합이 가장 안전합니다.
- 실존 건물은 게임 속에서 재현하는 정도는 대체로 괜찮지만, 브랜드 로고나 상호는 패러디로 바꾸세요.

## 4. 건축 도구와 26.x·Folia 호환

| 도구 | 26.x | Folia |
|---|---|---|
| WorldEdit 7.4.x | 26.1, 26.2 (26.3은 개발 중) | **지원** |
| FAWE (빠른 WorldEdit) | 26.1, 26.2 | 미지원 |
| goBrush, VoxelSniper 계열 | 업데이트는 있음 | 미지원 |
| Axiom | 26.3까지 | 공식 미지원 |
| Chunky (미리 생성) | 26.1 새 구조 대응 | **지원** |
| MCA Selector (청크 잘라붙이기) | 26.1~26.3 | — |

모두 [원문] 저장소 기준입니다.

**결론: 건축 서버와 운영 서버를 나눕니다.**
- **건축 서버:** Paper 26.2 + FAWE·브러시·Axiom 등으로 마음껏 짓습니다.
- **운영 서버:** Folia(하나의 큰 도시)에 완성된 월드를 복사합니다.
- `.litematic` 파일은 WorldEdit이 바로 못 읽으므로 `.schem`으로 변환해야 합니다.

## 5. 「하나의 큰 도시」 + Folia에서 꼭 지킬 것

- **Folia는 사람이 흩어져 있어야 빨라집니다.**
  - 대략 512블록 안에 모인 무리는 같은 지역(한 스레드)으로 묶입니다. [원문·추론]
  - 그래서 **경찰서·병원·공항·항구·은행 같은 거점을 1km 이상 떨어뜨려** 사람이 자연스럽게 퍼지게 설계하세요.
- **건물 내부는 별도 월드로:** 들어갈 수 있는 큰 건물(경찰서 내부, 병원 내부 등)은 별도 월드로 두면 바깥 도시의 부하가 줄어듭니다. [추론]
- **미리 생성하고 경계를 겁니다:** Chunky로 맵 전체를 미리 생성하고 월드 경계를 걸어, 운영 중에 새 땅이 생성되지 않게 합니다. [원문]
- **서버 설정:** `simulation-distance`는 낮게(3~4), `view-distance`는 높게 잡습니다. 공개 구역에서는 레드스톤·호퍼를 금지합니다. [원문·추론]
- **우리 플러그인의 Folia 호환 상태:**
  - 이미 Folia 호환입니다(`folia-supported: true`).
  - 다른 플러그인을 추가할 때는 **Folia 지원 여부를 먼저 확인**하세요. Folia는 지원 표시가 없는 플러그인을 아예 불러오지 않습니다.

## 6. 추천 순서
1. **기획 (1주):** 도시 크기(예: 4×4km)와 랜드마크 10~20개 목록, 거점 배치(서로 1km 이상)를 정합니다.
2. **데이터 (3~7일):** OSM과 GIS건물통합정보를 합쳐 `.osm`을 만듭니다.
3. **Arnis 생성 (1~2일, 여러 번 반복):** 옵션을 조정하며 다시 생성합니다.
4. **26.x 변환 (1~2일):** 백업 → 로컬 Paper 26.2에서 열기 → Chunky로 전체 로드 → 검수
5. **랜드마크 (랜드마크당 20~200시간):** 건축 서버에서 직접 짓습니다. Arnis 랜드마크 교체 기능에 등록해 둘 수 있습니다.
6. **채우기 (2~8주):** 박스형 건물을 라이선스 확실한 팩이나 의뢰 건물로 교체합니다.
7. **최적화 (1주):** 엔티티와 블록 엔티티를 점검하고 서버 설정을 조정합니다.
8. **부하 테스트 (2~3주):** 봇으로 테스트하고 spark로 측정합니다.
