# studio — 진보 커뮤니티의 목소리를 전하는 정치 채널 제작 도구

**다룰 주제와 채널의 주장 = 진보 커뮤니티의 반응과 다수 의견**(글·댓글·공감 수), **사실 = 뉴스 기사**.
원할 때 지금 뜨는 주제를 보고 골라서 **10분 묶음**(연관 주제 2~3개)이나 **3분 단독**(주제 1개) 대본을 바로 만든다.
주제 선정·대본 초안(topicradar)과 자료 수집·프리미어 XML(newsclip)을 한 저장소에서 돌리고, 도구는 timeline.xml까지만 만든다
(내레이션은 AI 음성을 직접 만들어 올린다).

```
studio/
  pyproject.toml        uv 워크스페이스(core · topicradar · newsclip)
  channel.yaml          채널 정체성·피드·커뮤니티 게시판·주제판·대본 길이·선호/차단 출처·API 예산
  .env.example          키 목록
  core/                 studio-core: 설정, Claude 래퍼(토큰 로그), HTTP 재시도, 텍스트 유틸, 시연용 fixture 전송계층
  topicradar/           collect / board / video / rewrite / export / import-script / made / history / probe
  newsclip/             run / review / xml / search
  app/                  studio 화면(브라우저): 아래 모든 단계를 버튼으로 — studio.command(맥) · studio.bat(윈도우)
  daebonsil/            claude.ai 아티팩트 원본: 제작실(주제→대본→음성→자료·XML 한 화면), 대본실(대본만)
  data/                 studio.db, logs/llm_usage.jsonl, schedule/날짜.yaml, 검색 캐시·API 사용량
  projects/날짜_시각_형식/  (예: 2026-10-08_1805_long) report.md script.txt narration.wav* narration.srt* scenes.json assets/ assets.json timeline.xml
  docs/sources.md       데이터 소스 조사 메모   docs/demo/ 시연 결과
```
\* 사용자가 만든다. `core/`는 두 패키지가 같이 쓰는 설정·LLM·HTTP 코드를 한 곳에 두려고 추가한 공용 패키지다.

## 화면으로 쓰기 (권장)

명령어 없이 브라우저 화면 하나로 씁니다. 화면은 이 컴퓨터에서만 열립니다(127.0.0.1:8760).

1. **코드 받기**: GitHub에서 **Code → Download ZIP** 후 압축 풀기(또는 `git clone`).
2. **실행**: 폴더 안의 **`studio.command`(맥)** 또는 **`studio.bat`(윈도우)** 더블클릭.
   처음 한 번은 uv(파이썬 도구)·파이썬·패키지를 자동으로 설치하느라 몇 분 걸리고, 끝나면 브라우저가 열립니다.
   - 맥에서 "확인되지 않은 개발자" 경고가 뜨면: 파일을 **우클릭 → 열기**. ZIP으로 받았다면 터미널에서 `chmod +x studio.command`가 필요할 수 있습니다.
   - 영상 자료를 쓰려면 ffmpeg 설치(맥 `brew install ffmpeg`, 윈도우 `winget install Gyan.FFmpeg`). 없으면 화면이 알려 줍니다.
3. **설정 탭**: API 키 붙여넣기(네이버·YouTube. **Claude API 키는 선택** — 없으면 아래 '대본실'로) → 내 채널 ID → **게시판 점검**(목록·본문·댓글이 읽히는지 확인) → 말투·분당 글자 수.
4. **주제판 탭(홈)**: **[주제판 만들기 / 새로 모으기]** — 수집 → 최근 24시간 커뮤니티 글로 **지금 뜨는 주제**를 반응도 순으로(1~2분).
   주제마다 **커뮤니티 주장**(공감 많은 글·댓글로 정리한 다수 의견 = 그 영상에서 채널이 할 말), 근거 논리, 소수 의견,
   대표 글·댓글(공감 수), 기사 수가 보인다. 위에는 서로 이어지는 주제 2~3개의 **10분 묶음 추천**이 있다.
   - 주제 하나 → **[3분 만들기]**
   - 추천 묶음 → **[이 묶음으로 10분 만들기]**, 또는 주제 2~3개를 체크 → 아래 막대의 **[10분 묶음 만들기]**
   - 누르는 즉시 대본을 쓰고 프로젝트 화면으로 간다. 같은 판에서 여러 편을 만들어도 된다(만든 주제엔 '만든 영상' 표시).
5. **프로젝트 화면**은 위에서 아래로 따라가면 됩니다.

| 단계 | 화면에서 하는 일 |
|---|---|
| 1 계획 | 주제·반응도·커뮤니티 주장·분량·근거 기사, 10분 묶음이면 주제를 잇는 고리. 제목 후보는 눌러서 복사. 주제를 바꾸려면 주제판에서 새로 만든다 |
| 2 대본 | 바로 고치고 **저장** → 점검(목표 글자 수, 예상 길이, 25자 줄, 출처, 기사에 없는 수치, 커뮤니티 글 그대로 옮김 등) 다시 표시 |
| 3 음성·자막 | **[타입캐스트용 대본 복사]**(읽는 문장만) → 타입캐스트 웹에 붙여넣고 음성(mp3·wav) 다운로드 → **끌어다 놓기** → 자막(SRT)을 대본에 맞춰 자동 생성. 실제 읽는 속도(분당 글자 수)가 보이고 버튼 하나로 길이 기준에 반영 |
| 4 자료 | **자료 수집 시작** → 장면별 사진·영상 후보 중 고르기, 영상 시작 초 조정 → **저장 + XML 다시 만들기** |
| 5 프리미어 | **timeline.xml 내려받기** → 프리미어 파일 → 가져오기 |
| 6 업로드 기록 | 올린 영상 주소와 실제 제목 → **기록하기**(성과 분석용) |

- **성과 탭**: 커뮤니티 반응도 vs 조회수, 10분 묶음 vs 3분 단독, 카테고리별 성과.
- **자동 수집**: 화면을 켜 둔 채 스위치를 켜면 07시부터 2시간마다 커뮤니티·뉴스를 모아 둔다(게시판 목록 1~2쪽만 읽으므로
  오래 안 모으면 그 사이 글을 놓친다). 주제판과 대본은 원할 때 만든다. Slack 주소를 넣으면 주제판 요약이 간다.
- 키는 `.env`, 나머지 설정은 `channel.yaml`에 저장됩니다(화면에서 고쳐도 파일 주석은 그대로). 아래 명령어 방식과 같은 데이터를 씁니다.

## 한 화면으로 다 하기 — claude.ai 제작실

**제작실:** https://claude.ai/artifact/4c9nubZb4WfXA7jiHq9Rr8 (내 계정에서만 열린다)

설치 없이 claude.ai 화면 하나로 **주제 고르기 → 대본 → 음성 → 자료·timeline.xml**까지. 생각하는 일(주제 묶기·
커뮤니티 의견 정리·대본·제목)은 **내 Claude**가, 인터넷이 필요한 일(커뮤니티·뉴스 수집, 사진·영상 자료,
timeline.xml)은 **클라우드 작업자**(Claude Code 세션, 네트워크 Full)가 한다. 화면의 버튼이 제작실에 댓글을 남겨
"Claude에게 보내기"를 하면 제작실을 지켜보는 작업자 세션이 깨어나고(안 되는 화면에서는 붙여 넣을 글을 보여 준다), 작업자는 [docs/workroom.md](docs/workroom.md) 절차대로 `studio_app.workroom`을
돌려 결과를 아티팩트 데이터·자산에 올린다.

1. **주제 고르기**: [새로 모으기] → 사이트별 글 수 확인(막힌 사이트 표시, 눌러서 빼기) → [Claude로 주제 묶기·의견 정리]
   → 주제 하나 [3분 단독]·[세로 쇼츠] / 2~3개 [10분 묶음](추천 묶음은 한 번에)
2. **대본**: [Claude로 대본 쓰기](한 줄에 한 문장) → 길이·헤더·숫자·뭉뚱그린 말·그대로 옮김 점검 → [점검대로 고쳐 쓰기] → 제목·썸네일
3. **음성**: [타입캐스트용 복사] → 타입캐스트에서 받은 음성을 올리면 **브라우저 안에서** 길이·문장 사이 쉼을 분석하고,
   음성 인식용으로 작게 압축해(Opus webm, 10분에 2MB쯤, Chrome·Edge) 제작실에 올린다. 4단계에서 작업자가 그 음성을
   **듣고**(faster-whisper) 대본 글자와 들린 글자를 맞대어 문장·쉼표 경계마다 실제로 들린 시각을 찾고, 그 근처의
   실제 쉼에 붙여 자막·장면 시각을 정한다. 자막 글은 대본 그대로(인식 글자는 시각에만 쓴다).
4. **자료·XML**: [자료 모으고 timeline.xml 만들기] → 작업자가 장면 나누기(말 덩어리 하나 = 사진 한 장)·대사를 읽고 장면별 검색어·사진 받기·timeline.xml(사진만, 음성 트랙 없음)
   → 장면별 자료를 화면에서 확인 → 압축을 풀 폴더를 적고 [압축 파일 받기](사진·출처 표시 그림 + timeline.xml + 장면목록.txt + 영상후보.txt)
   → 프리미어에서 가져오기. **음성과 자막은 직접 넣는다**(음성을 3단계에서 올려 두면 장면 시각을 음성에 맞추고, 안 올리면 대본 길이로 어림).
   - 장면 나누기: 문장 끝·쉼표 뒤·따옴표 인용이 시작하는 곳 앞에서만 자른다(문장·인용 한가운데는 안 자름). 30자 넘는 문장만 나누고,
     2초보다 짧은 덩어리는 다음과 묶는다. 사진 한 장에 대사 한 덩어리.
   - 장면마다 다른 사진: 사진 검색어는 '주제 대표 말 + 그 장면에만 나오는 말'이고, 앞 장면에서 고른 사진은 크게 감점한다.
   - 영상: 주제마다 장면 3개 중 하나는 유튜브에서 영상 후보를 찾는다. 클라우드에서는 유튜브 영상 받기가 막혀(403)
     영상은 링크로만 남긴다(화면의 장면 카드, 압축 파일의 `영상후보.txt`: 제목·채널·시작 지점). 내 PC의 studio는 영상을 받아 넣는다.

**채널 두 개**: 제작실 맨 위 [채널]에서 **정치는푸르다**(진보 정치, `channel.yaml`)와 **오늘증시 김시연**
(증시 뉴스, `channel.stock.yaml`)을 바꿉니다. 증시 채널은 주제를 증시 기사(국내 마감 시황·종목·금리·환율·밤사이 미국 증시)로
고르고, 커뮤니티는 쓰지 않습니다(증권·경제 뉴스 피드 12곳 + 시황 네이버 검색어). 대본은 애널리스트 브리핑처럼 숫자 → 원인 → 영향 →
체크포인트 순으로 빠르게, 투자 권유(사라·팔라·목표가·수익 보장)는 쓰지 않고, 마무리 인사에 "투자 권유가 아니며…"를 붙입니다.
채널마다 수집·주제·프로젝트 데이터는 따로 둡니다(`data-stock/`, `projects-stock/`, 아티팩트 `stock_*` 컬렉션).
증시 채널 영상 소스는 사진이 아니라 장면마다 자동으로 그린 슬라이드(채널 색 흰색→민트, 큰 숫자·상승 빨강/하락 파랑)입니다.
제목·썸네일과 함께 추천 해시태그를 만들고, 채널 고정 태그(정치: #정치 #정치뉴스, 증시: #주식 #증시뉴스)를 늘 맨 앞에 붙입니다.

**자유뉴스365**(강경 보수 논평, `channel.right.yaml`): 국민의힘 지지 중심의 강경 보수 시선 — 뉴스 전달이 아니라 의견을 말한다
(분량의 3분의 2 이상이 채널의 의견, 사실은 짧게 확인만). 이재명 정부·민주당을 강하게 비판하고, 싸우지 않는 국민의힘 지도부도 짚는다.
보수 성향 커뮤니티는 대부분 자동 수집을 막아(에펨코리아·엠엘비파크·디시인사이드) 시선은 보수 언론 사설·칼럼(조선일보 오피니언·
동아일보 사설·한국경제 오피니언·데일리안 오피니언·펜앤드마이크 칼럼)에서 가져온다(일간베스트는 5·18 왜곡·혐오 글이 중심이라,
자유일보는 부정선거 주장을 퍼뜨려 와서 쓰지 않는다. 조갑제닷컴은 강경파를 비판하는 결이라 꺼 둠). 넘지 않는 선: 부정선거 음모론, 5·18 왜곡, 12·3 계엄 미화,
지역·여성·외국인·성소수자 혐오. 사실은 기사로만.

**10분·3분 대본의 좋아요 부탁**(정치 채널·자유뉴스365, `script.like_ask`): "타 진영에서 싫어요를 많이 누르는 바람에 저희 영상이
잘 노출되지 않고 있습니다. 여러분이 좋아요 한 번 눌러 주시면 큰 힘이 됩니다." — Claude가 쓰지 않고 프로그램이 대본 중간에 넣는다
(주제가 둘 이상이면 둘째 주제 바로 앞, 하나면 3분의 1쯤 지난 곳). 끝 인사처럼 늘 들어가고, 빠지면 점검이 잡아 [점검대로 고쳐 쓰기]가 바로 넣는다.
쇼츠·증시 채널에는 넣지 않는다.

**제목은 검색되는 제목으로**(정치 채널·자유뉴스365): 홈 피드에 잘 안 뜰 때는 검색으로 들어오는 시청자가 첫 마중물이라, 제목 앞쪽에
실제 인물 이름·위원회/국정감사 이름·법안/사건 이름을 그대로 넣고 그 뒤에 "논란 총정리·쟁점·발언 팩트체크"처럼 내용을 붙인다
(예: "[인물] [법안] 논란 총정리, [위원회] 국감 쟁점과 발언 팩트체크"). 1안은 검색 키워드형, 2·3안은 키워드 + 채널의 주장 한 마디.
논평형·수사 의문형만으로 된 제목은 쓰지 않는다. 증시 채널은 원래대로 숫자·지수·종목 이름이 앞.

**세로 쇼츠**(정치 채널·자유뉴스365, 증시 채널은 아직 없음): 주제 하나로 1분 안쪽(490~590자) 대본. 첫 1~3초(첫 문장, 25자 안쪽)에는
가장 강력한 소식 하나(가장 센 발언 원문·믿기 힘든 숫자·결정적 사실)를 바로 — 질문으로 던져도 소식은 그 안에, 이어 처음 10초(둘째·셋째 문장)는
그 소식의 앞뒤를 가장 자극적으로 — 인사·예고 없이, 넷째 문장쯤 "진짜 문제는 따로 있다"로 끝까지 볼 이유를 건다(자극은
기사·커뮤니티에 있는 사실로만). 끝은 시청자 질문("당의 책임일까요, 대통령의 책임일까요? 여러분 생각을 댓글로 남겨 주세요.")으로
맺고, 제목 칸에서 같은 쟁점의 **고정 댓글**(영상을 올린 뒤 달고 고정할 한 문장)도 만든다. 화면 점검이 첫 문장 길이(32자 넘으면)와
끝 질문을 확인한다. 쇼츠는 '충격'·'경악' 같은 센 말도 대본·제목·상단 제목에 허용한다(가로 영상은 그대로 금지). 끝 인사는
구독 + 오른쪽 하트 부탁(`script.shorts_outro`). timeline.xml은 세로 1080×1920: 사진은 가운데 칸(4:3)에 크게, 위쪽에는 상단 제목
(대본 칸의 '상단 제목' = 썸네일 문구)이 영상 내내 뜬다. 디자인은 채널마다(`shorts.style`): 정치는푸르다는 흰·노랑 글씨 + 검은 테두리에
흐린 사진 바탕, 자유뉴스365는 남색·빨강 띠 + 블랙한산스에 위아래 검은 바탕. 자막.srt는 한 줄 14자 안팎, 해시태그에 #Shorts가 붙는다.

사진·영상 검색에는 클라우드 환경 설정의 Environment variables에 `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`
(그리고 `YOUTUBE_API_KEY`)가 있어야 한다. 클라우드 서버는 해외에 있어 더쿠·오늘의유머·다모앙은 막힌다
(클리앙·뽐뿌·보배드림은 읽힌다). 화면 원본은 `daebonsil/workroom.html`, 만들기는 `uv run python daebonsil/build.py`.

## 운영 순서(명령어)

0. (처음 한 번) `topicradar probe` — 커뮤니티 게시판 목록·글 상세(본문·댓글·공감)가 읽히는지 확인. 뽐뿌 게시판 id, 더쿠 정치 카테고리 주소는 미확인이라 여기서 맞춘다
1. `topicradar collect` — 하루 몇 번(예: 2시간마다) 돌려 커뮤니티·뉴스를 모아 둔다
2. `topicradar board` — 지금 뜨는 주제판(반응도 순, 커뮤니티 주장, 10분 묶음 추천)
3. `topicradar video --format short --pick 1` (판 1위로 3분) / `topicradar video --format long --bundle 1` (추천 묶음 1로 10분)
   / `--topics <id>,<id>`로 직접 → `projects/<영상 ID>/report.md`·`script.txt`
4. `script.txt` 수정 — `#TODO`·`#확인` 처리(리포트 하단 '대본 점검' 참고). 대본에는 출처 줄을 넣지 않고 근거 기사는 리포트에 남는다
5. AI 음성: 화면의 [타입캐스트용 대본 복사] → 타입캐스트 웹에서 음성 다운로드 → 화면에 올리면 `narration.wav`(변환)와
   `narration.srt`(자동)가 생긴다. 자막은 대본을 알고 있는 상태에서 음성의 쉼(문장 사이)에 문장 경계를 맞춘다
   (`newsclip/autosub.py`, ffmpeg silencedetect). 제작실 작업자는 여기에 음성 인식(`newsclip/asr.py`)을 더해 들린 말에 맞춘다. 직접 녹음했다면 프리미어 전사 → 캡션 → **SRT 내보내기** → `narration.srt`
6. `newsclip run --project projects/<영상 ID>`
7. `newsclip review --project …` (http://localhost:8765) — 후보 교체·건너뛰기·영상 시작 초 조정 → 저장 시 XML 재생성
8. 프리미어 **파일 → 가져오기 → `timeline.xml`** (V1 화면, V2 출처 표시, A1 내레이션. 자막은 넣지 않는다 — 필요하면 `channel.yaml timeline.subtitles: true`)
9. 업로드 → `topicradar made --project … --video-id <유튜브ID> [--title "실제 제목"]`
10. 가끔 `topicradar history --weeks 4` — 반응도와 조회수, 10분·3분 형식별 성과

## 설계 요점

**주제와 주장 = 진보 커뮤니티, 사실 = 뉴스 기사.** `channel.yaml`의 `communities`(기본: 다모앙 자유게시판·보배드림 정치·뽐뿌·더쿠 HOT·클리앙 모두의공원)를
robots.txt를 지키며 요청 사이 1초씩 쉬어 읽는다.
1. **목록**(1쪽): 제목·댓글 수·추천 수(`vote_pattern`이 있으면)·시각. 자유게시판은 정치 어휘로 거른다.
2. **글 상세**: 수집 때마다 반응 큰 글 `detail_posts`(기본 8)개만 본문 앞부분·댓글 내용·댓글 공감 수·글 공감 수를 읽는다.
   이미 읽은 글은 댓글이 5개·30% 이상 늘었을 때만 다시 읽는다. 닉네임 등 글쓴이 정보는 저장하지 않는다.
   본문·댓글 위치는 선택자(`body_selector`·`comment_selector`·`vote_selector`)를 주면 그대로, 없으면 '가장 긴 글 덩어리 = 본문',
   'class에 comment·reply·cmt가 든 반복 요소 = 댓글'로 찾는다(`htmltree.py`, 표준 라이브러리만). 댓글을 따로 불러오는 사이트(일부)는
   댓글 내용은 못 읽고 목록의 댓글 수로만 반응을 잰다 — `probe`가 알려 준다.
3. 커뮤니티 제목에서 겹치는 핵심어로 네이버 뉴스 검색어를 만들어(`board.derived_queries`) 사실 근거 기사를 더 모은다.
4. **반응도**(0~100, 주제 점수의 전부) = 100 × log(1 + 글 수 + 댓글/20 + 공감/10) / log(1 + 30) + 급상승 가점(직전 같은 길이 구간 대비, 최대 +10).
   기사 수·경쟁 채널은 점수에 넣지 않는다. 판에는 글이 `board.min_posts`(기본 2)개 이상이거나 글 하나라도 반응도 50 이상인 주제만 오른다.
5. **커뮤니티 의견**: 주제마다 다수 의견(stance) 한 문장, 근거 논리 2~4개, 소수 의견, 궁금해하는 것. '동의'는 공감 수를 더 크게 본다
   (글 무게 = 1 + 공감/10 + 댓글/40 — 댓글이 많은 건 논란일 수도 있어서). Claude는 판 상위 12개 주제를 한 번에 정리하고 10분 묶음도 고른다.
   오프라인은 공감 많은 글 제목과 공감 많은 댓글을 그대로 옮긴다.
6. **10분 묶음 추천**: 같은 인물·기관·사건명이 겹치는 주제 2~3개(정당명 같은 일반어만으로는 안 묶음)와 잇는 고리 한 문장.
7. **영상 계획**: 10분 묶음은 첫 주제를 조금 길게(1.3배) 분량을 나누고, 대본 목표 글자 수 = 분 × `script.chars_per_minute`(기본 300) ± 10%.
   음성을 올리면 실제 읽는 속도(쉼 포함)를 재서 보여 주고 버튼으로 기준을 바꿀 수 있다.

**채널 관점과 커뮤니티 글의 자리**: 채널은 친이재명 시선이다. 이재명 대통령은 공격하지 않고 국정 방향을 지지하되,
무조건 민주당 편은 아니다 — 문제가 민주당 안에 있으면(대통령과 엇박자, 지도부의 판단 착오, 개혁 지연) 친이재명 지지층의
눈으로 짚고(주제 각도 '당내 비판'), 국민의힘·극우 세력의 문제면 그쪽을 짚는다. 원인을 억지로 상대 진영 탓으로 돌리지 않고,
원인이 여럿이면 무게를 나눠 가장 큰 원인을 분명히 한다. 다룰 주제와 채널의 시선은 커뮤니티 다수 의견으로 정한다.
사실·수치·인용은 기사에서만 쓰되 대본에는 출처 줄을 넣지 않는다(근거 기사는 리포트·계획에 남고, 점검기가 기사에 없는 수치·인용을 경고).
커뮤니티 글은 사실 근거가 될 수 없고,
글·댓글을 그대로 길게 옮기면 경고한다. 커뮤니티에서 나온 의혹은 의혹으로만, 닉네임·사이트 이름은 대지 않는다.
기사가 아직 없는 화제도 판에는 오르지만 대본의 사실 부분은 `#TODO`로 남는다. 비속어·비하 별명은 쓰지 않는다(법적·광고 제한 위험).

사이트 개편으로 글을 못 찾으면 수집 표에 `community:사이트 실패 … post_pattern 확인`이 뜬다
→ `topicradar probe --name 사이트`로 보고 `post_pattern`/`list_url`/선택자를 고친다. 각 사이트 이용약관은 운영자가 확인할 것(docs/sources.md §12).

- 수익화 안전도는 점수에 넣지 않고 `risk_flags`로만 표시(노란딱지 표현, 수사·재판 중 사안, 여론조사 공표 요건, 기사 없는 주제).

**대본 점검**: 생성 경로와 상관없이 `validate_script`가 목표 글자 수(형식별), `## 헤더`가 고른 주제와 맞는지(10분 묶음은 `## 정리`까지),
수집 기사에 없는 수치·인용, 남아 있는 출처·주석 줄, 커뮤니티 글 그대로 옮김, 금지 표현(충격·경악·난리…)을 검사해 리포트에 싣는다.

**마무리 인사**: 대본 끝에는 언제나 `channel.yaml`의 `script.outro`("더 나은 대한민국을 위해서 정치는푸르다 채널 구독해주시고, …")를
한 단락으로 붙인다. Claude가 쓰지 않고 프로그램이 붙이며(제작실·대본실·studio 모두), 빠지면 점검이 알려 준다.

**사실부터 또렷하게**(모든 말투 공통, 가장 먼저): 사건을 처음 꺼낼 때 누가·언제·어디서·무슨 말을 했는지 기사 그대로
(핵심 발언은 따옴표로) 말한다. "그 글"처럼 가리키기만 하거나 "본질·공세·프레임·말꼬리" 같은 말로 뭉뚱그리는
예고편식 문장은 쓰지 않고, 주장과 비유는 사실 다음에 온다. 점검기는 뭉뚱그린 말이 3번 넘으면 경고한다.

**말투**: `channel.yaml`의 `script.tone`으로 고른다. 기본 `확신형+입담형` — 재미가 첫째: 첫 3초에 가장 센 사실 하나(누가 언제 한 말 그대로),
기사를 읽지 않고 이야기로(누가 → 언제·어디서 무엇을 → 그런데 → 한 방), 상대의 예전 말과 지금 행동을 나란히 놓는 풍자, 40~60대가 아는 일상 비유,
단락 끝 펀치라인(주제당 2~3개), 짧고 센 마무리. 풍자 대상은 그 사안에서 문제를 만든 쪽(상대 진영이든 당내 인사든)의 행위·논리이고(이재명 대통령은 풍자하지 않음) 인신공격·별명·비속어는 금지다.
`확신형`, `해설형`(차분한 해석)도 있다. 형식 규칙(한 줄에 한 문장, `## 헤더`, 출처 줄 없음)은 말투와 상관없이 같다.
점검기는 기사체 종결("~라고 밝혔다")이 3줄 이상이거나 비속어가 있으면 경고한다. 오프라인 경로는 연결 문장 정도만 반영하고, 입담과 주장 다듬기는 Claude 경로에서 나온다.

**Claude 호출**: 주제판 한 번에 군집·의견 정리 2회, 영상 하나에 제목·대본 2회 내외, newsclip 장면 1회. structured outputs로 JSON 스키마를 강제하고,
시스템 프롬프트(채널 정체성·규칙)는 고정해 프롬프트 캐시를 맞춘다. 안전 분류기 거절 시 서버 측 대체 모델(`fallbacks: "default"`)로 재시도한다(끄려면 `STUDIO_LLM_FALLBACKS=0`).
토큰 사용량은 호출마다 `data/logs/llm_usage.jsonl`에 남는다.

**newsclip 소스 우선순위**(Google 키가 없으면 네이버가 그 자리를 대신해 1순위):
| 장면 | 순서 |
|---|---|
| 사진(인물·기관·장소) | google_image → wikimedia → naver_image (Google 없으면 naver → wikimedia) |
| 사진(사건·현장)·broll | google_image → naver_image |
| 영상(발언·회의·현장) | youtube_video(방송사 채널 제외, KTV·국회방송·정당 채널 가점) → 정지 이미지 |

YouTube `search.list`는 1회 100 units라 검색어 7일 캐시, 동시 동일 요청 합류, 일일 예산(`budget.youtube_search_per_day`)으로 쿼터를 지킨다.
사진은 1920×1080으로 커버 크롭해 저장하므로 프리미어 Scale 100이 화면을 꽉 채우고, 줌(100→104, ease-out)은 선형 키프레임 5개로 근사한다(홀수 장면 줌인·짝수 줌아웃).

## 출처 표기와 저작권 (법률 자문 아님)

- 라이선스 필터는 걸지 않는다(채널 결정). 대신 모든 자료의 출처 URL·도메인·채널·작가를 `assets.json`에 남기고 **V2 트랙에 출처 자막**을 넣는다.
  표기: `출처: {도메인 또는 채널명}`, Wikimedia는 `사진: {작가} / Wikimedia Commons / {라이선스}`.
- **출처 표기는 이용 허락이 아니다.** 저작권법 제28조(공표된 저작물의 인용)·제35조의5(공정한 이용)의 범위인지는 용도·분량·대체 가능성에 따라 달라진다.
- 방송사 뉴스 채널은 Content ID 위험 때문에 기본 차단(`videos.blocked_channels`). 업로드 전 `review`에서 사람이 확인한다.
- 여론조사 인용 시 공직선거법 공표 요건(조사의뢰자·기관·기간·방법·표본·오차범위, 중앙선거여론조사심의위원회 참조 고지)을 리포트가 상기시킨다.

## 시연 (네트워크·키 없이)

```bash
uv run python scripts/demo.py
```
`fixtures/demo/stories.yaml`의 **가상 뉴스와 가상 커뮤니티 글·댓글**(가상 정당 한빛당·새한당, 익명 인물, example.com URL — 실존 사건·실제 게시글 아님)을
실제 RSS·네이버·유튜브 응답 형식과 게시판 목록·글 상세 HTML로 만들어(`fixtures/demo/build.py`) 다음을 차례로 실행한다:
collect → 10/8 18:00 주제판(+Slack) → 10분 묶음(추천 묶음 1) → 3분 단독 2편(판 1·3위) → 각 `made` → `history` → 10분 대본으로 샘플 SRT·무음 WAV 생성 → `newsclip run` → `newsclip xml --audio`.
결과는 `demo_root/`(전체)와 `docs/demo/`(리포트·대본·SRT·scenes/assets·timeline.xml·실행 로그)에 남는다.

- `STUDIO_FIXTURES`: 모든 HTTP를 fixture로 대체(파서는 실제 응답 형식을 그대로 읽음), 이미지는 생성기가, 영상은 ffmpeg 테스트 패턴이 대신한다.
- `STUDIO_LLM=offline`: 이 환경엔 Claude 키가 없어 휴리스틱으로 돈다. 오프라인 대본은 **기사 사실 문장 + 공감 많은 커뮤니티 글·댓글을 옮겨 둔 골격**이라
  분량이 목표보다 짧고, 말로 다듬을 곳은 `#확인`, 근거가 없으면 `#TODO`를 남긴다(지어내지 않음). 키를 넣고 같은 명령을 돌리면 Claude 경로로 간다.
- `STUDIO_NOW`: 단계마다 '현재 시각'을 고정해 실제 운영 순서를 재현.
- 시연 결과를 화면으로 보기: `STUDIO_ROOT=demo_root STUDIO_FIXTURES=fixtures/demo STUDIO_LLM=offline STUDIO_NOW=2026-10-08T18:20 uv run studio`
  (화면에서 버튼을 눌러도 가상 데이터로만 돈다).
